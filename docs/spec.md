# 샛길 기능·요구사항 명세 v2

2026-10-28

**빨강** = 꼭 구현 · **주황** = 목업 · **회색** = 발표만 · **스트레치** = 11/7 이후 여유 시 · ⚠️ = 결정 필요

## 개요

**샛길은 출퇴근 중 '걷는 구간'을 바꿔, 결심 없이 자연을 지나가게 하는 웹앱이다.** v2의 핵심 변경은 둘이다: 교통수단(대중교통)을 전제로 샛길을 재정의했고, 동선에 자연이 없을 때의 대체 로직을 넣었다.

| 항목 | 내용 |
| --- | --- |
| 정의 | 결심 없이, 자연을 지나는 하루 |
| 성격 | 지도 앱 대체 ❌ · 알림 오면 여유 있을 때 여는 앱 |
| 슬로건 | 걸음 대신 **계절**을 센다 |
| 샛길의 정의 (v2) | 출퇴근 **경로 전체**가 아니라 **걷는 구간**을 바꾸는 것. 탑승 횟수는 늘리지 않는다 |
| 교통수단 (v2) | 도보 · 대중교통 · 자동차. 대중교통이 기본 가정 |
| 형태 | 웹앱 (모바일 우선) |
| 탭 | 홈 · 경로 · 기록 · 마이 |
| 계정 | 이메일·비밀번호 가입(닉네임 포함, 인증 메일 없음) · 둘러보기. Supabase Auth. 소셜 로그인은 2차 |
| 지역 | 대구 우선. 서울 전환은 스트레치 (코드는 city 파라미터로 분리) |
| 데모 동선 | ⚠️ 대구 2호선 수성구청→반월당 퇴근 18:10, 한 정거장 먼저 내리기 (대중교통 추천) · 도보 대안: 수성구청→반월당 |

## IA

```
앱 실행 → 로그인 / 가입 / 둘러보기 → (처음이면) 출퇴근 설정(교통수단 포함) → 홈

홈                 경로                    기록            마이
├ 오늘의 퇴근길 카드  ├ 경로 상세 (추천 1 + 이 길로)  ├ 남기기        ├ 출퇴근 정보 수정
│  └ 다른 길 보기     ├ 다른 길 보기 (최대 3 + 최단)  ├ 모아보기(장소별) ├ 알림 설정
├ 오늘의 계절         ├ 걷는 중                  └ 장소 기록(켜켜)  └ 지역 (스트레치)
├ 오늘의 출근길(작게)  └ 주변 자연 (발표만)
└ 지역 토글(스트레치)
```

v1 대비: 홈의 중심이 "경로 리스트 3개"에서 **"카드 1장 + 다른 길 보기"**로 바뀌었다. 매일 3개 중 고르는 것은 결심 비용이고, 페인포인트와 모순이기 때문이다. 가입은 이메일·비밀번호·닉네임 세 칸이다. 그 외 개인정보 입력은 없다.

## 사용자 플로우

1. **로그인** — 이메일·비밀번호 (가입 시 닉네임 추가). 둘러보기는 계정 없이 데모 동선 열람
2. **출퇴근 설정** — 출발 · 도착 · 출퇴근 시간 · **교통수단**. 대중교통이면 노선·정류장 자동 조회 (처음 1회)
3. **알림** → 홈의 오늘의 퇴근길 카드 (행동 유형: 돌아가기 · 한 정거장 먼저 · 늦추기 · 고개 돌리기 · 도착 후)
4. **"이 길로"** → 경로 상세 (추천 1개). 비교가 필요하면 "다른 길 보기"
5. **걷는 중** — 자연 구간 도착 시 안내 → 남기기
6. **모아보기** — 장소별로 계절 기록이 쌓임

대중교통 퇴근의 걷는 구간은 세 토막이다. 샛길은 이 중 하나만 바꾼다.

| 패턴 | 바꾸는 구간 | 예시 |
| --- | --- | --- |
| 앞 도보 바꾸기 | 회사 → 정류장 | 사무실 → 경상감영공원 지나 중앙로역 |
| **한 정거장 먼저 내리기** | 전 정거장 → 집 | 범어역 대신 수성구청역에서 내려 신천 따라 +12분 |
| 뒤 도보 바꾸기 | 정류장 → 집 | 출구 반대편으로 나가 공원 통과 |
| 지원 안 함 | 중간 하차 후 재탑승 | 환승 대기·요금·결심이 생겨 원리와 어긋남 |

## 핵심 기능 상세

### F-01 로그인 · 가입

- **가입** 이메일 · 비밀번호 · 닉네임. 프론트가 Supabase `signUp` 호출, 닉네임은 `options.data.nickname`. 인증 메일 OFF
- **로그인** 이메일 · 비밀번호. 프론트가 Supabase `signInWithPassword` 호출 → access token
- **서버** 모든 인증 요청의 `Authorization: Bearer {token}`을 Supabase JWKS로 검증. 최초 요청 시 `sub`로 User 생성, 닉네임은 `user_metadata.nickname`, 없으면 "샛길러"
- **둘러보기** 토큰 없음. 데모 동선 조회만 허용, 저장·기록은 로그인 필요
- **데모 계정** `scripts/seed_demo.py`로 생성. 심사 제출 시 이메일·비밀번호 동봉
- **범위 밖** 소셜 로그인, 비밀번호 재설정, 이메일 변경

### F-02 출퇴근 설정

- **입력** 출발 · 도착 · 출근 시각 · 퇴근 시각 · 교통수단(도보 / 대중교통 / 자동차)
- **처리** 대중교통이면 대중교통 API(ODsay 또는 TMAP)로 노선·정류장 목록 조회 → 사용자가 확인. 데모 동선은 2호선 정류장 좌표를 테이블에 미리 넣어 API 없이 동작
- **저장** 좌표는 기기에만. 서버에는 동 단위 · 시각 · 교통수단 · 노선 · 정류장 ID. **경로 생성 요청 때만 좌표를 전송하고 서버는 저장하지 않는다**

### F-03·04 샛길 생성 + 녹지 % + 이벤트 점수

- **입력** 출발·도착 좌표, 교통수단, 정류장 목록
- **처리**
  1. 교통수단별로 **걷는 구간**을 정한다. 도보 → 전체 / 대중교통 → 앞 도보 · 뒤 도보 · 한 정거장 먼저(전 정거장→집) / 자동차 → 도착 후 반경 10분
  2. 각 걷는 구간의 최단 보행 경로를 TMAP 보행자 API로 받는다 (기준선)
  3. 기준선 주변 600m 안의 자연 지점(큐레이션 테이블 + OSM 공원 입구·하천 접점·가로수 양 끝)을 경유지로 넣어 후보 경로 5~6개 생성
  4. 경로를 50m 구간으로 잘라 PostGIS로 녹지 근처 여부 판정 → 녹지 %. 물가·다리·노을 방향 → 이벤트 점수
  5. **+15분 이내이고 최단 대비 녹지 +10%p 이상**인 것만 후보. 녹지 높은 순 최대 3개
  6. 후보 0개면 F-15로
- **출력** 이름 · 태그 · `legType` · +시간 · 녹지 % · 이벤트 점수 · 하이라이트 · 경로선 · 마커 · 하차 정류장
- **성능** 데모 동선 3개는 사전 계산 캐시. 신규 동선은 10초 허용

### F-15 대체 로직 (신규)

**도시 동선의 절반은 자연이 없다. 빈 화면을 보여주지 않되, 억지 샛길도 만들지 않는다.** 위에서 아래로 내려가며 처음 조건을 만족하는 단계가 오늘의 카드가 된다.

| 단계 | 조건 | 행동 유형 | 카드 예시 |
| --- | --- | --- | --- |
| 1 | 걷는 구간 안에 샛길 있음 | 돌아가기 | "12분 돌아가면 신천 노을" |
| 2 | 없음 + 대중교통 | 한 정거장 먼저 | "수성구청역에서 내리면 +12분, 신천 1.1km" |
| 3 | 없음 + 이벤트 있음(노을 ±20분 · 물가 · 다리) | 늦추기 · 고개 돌리기 | "6분 늦추면 다리 위 노을" / "지금 왼쪽, 억새" |
| 4 | 없음 | 도착 후 샛길 (집·회사 반경 10분) | "퇴근 후 집 앞 공원 7분" |
| 5 | 그것도 없음 | 없음 | "오늘 동선엔 자연이 없어요" + 주변 자연 |

3단계가 중요하다. 신천 위 다리를 건너는 동선은 녹지 %로는 0에 가깝지만 노을·물·개방감이 있다. 녹지 %만 보면 대구 동선의 좋은 절반을 버린다.

### F-05 오늘 카드 (AI)

- **위치** 홈 › 오늘의 퇴근길 카드
- **입력** 서버 점수 1위 경로 · 대체 단계 · 행동 유형 · 퇴근 시각 · 일몰 · 날씨 · 미세먼지 · 계절 상태 · 장소 한 줄 설명(큐레이션)
- **처리**
  1. 서버 점수 = 녹지 % + 이벤트 점수 + 가산(일몰 ±20분, 맑음, 계절) − 추가 시간 페널티 → **1위 결정은 서버**
  2. 퇴근 시각 − 일몰 시각과 대체 단계로 **행동 유형 결정** (서버)
  3. **LLM은 문장 2개와 이유 태그만 생성한다. 선택하지 않는다**
- **규칙** 장소 · 시각 · 거리 · 정류장 이름은 입력값만 사용. 2문장 이내. 이유는 하나만
- **예외** LLM 실패 → 1위 + 템플릿 문장 ("{정류장}에서 내리면 +{분}분, {장소}")
- **개인화** 사용자가 고른 태그(하천·공원·가로수) 횟수에 따라 가중치 ±0.2. 학습이 아니라 규칙이며 발표에서 "개인화 규칙"으로 부른다

### F-06 경로 비교

- 지도: 최단 회색 점선 · 샛길 초록 실선(자연 구간은 굵게) · 자연 주황 마커 · **하차 정류장 마커**
- 비교 3칸: 시간 · 녹지 % · 더 걷는 시간. 라벨 필수
- "이 길로" 버튼. 턴바이턴 안내는 만들지 않고 "카카오맵으로 안내" 딥링크로 넘긴다

### F-07 지역 전환 (스트레치)

- 녹지 · 큐레이션 · 정류장 데이터를 `city` 파라미터로 분리해 두고, 11/7 이후 여유가 있으면 서울 동선 1개(홍대입구→공덕, 경의선숲길)를 넣는다
- 여유가 없으면 서울 동선 1개를 오프라인에서 돌려 **발표 자료에 스크린샷 1장**

## 비기능 · 기술 스택

- 🔒 **개인정보** 정확한 위치는 기기에만 · 경로 생성 요청 때만 전송, 저장 안 함 · 서버엔 동 단위·정류장 ID만 · 기록은 나만 보기. 발표 초반에 먼저 말한다
- 👤 **계정** 이메일·비밀번호 가입 (Supabase Auth, 인증 메일 없음) · 둘러보기 · 심사용 데모 계정은 seed 스크립트로 생성해 제출 시 동봉
- 📱 **반응형** 모바일 하단 탭 4개
- ⚡ **성능** 데모 동선 사전 계산 · 신규 동선 10초 · 카드 5초
- 🌐 **배포** 외부 접속 URL
- 🤖 **AI** 판단은 서버 규칙, AI는 문장. 실패 시 템플릿 · 키는 서버에만
- 🏙 **도시 분리** 녹지 · 큐레이션 · 정류장 데이터는 `city` 파라미터로. 코드에 "대구" 하드코딩 금지
- 🎬 **데모** 동선 3개 사전 검증 · 알림 잠금화면 목업으로 시작 · 녹화 백업

### 스택

| 층 | 선택 | 이유 |
| --- | --- | --- |
| DB | **PostgreSQL + PostGIS (Supabase)** | 공간 질의가 핵심. 다른 선택지 없음. 호스팅 5분 |
